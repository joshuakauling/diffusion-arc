# B3: sequence packing with FlashAttention-3

In hindsight, we approached this in the wrong order. Before building padding
catalogs and increasingly complex batch-selection logic, we should have checked
whether other attention implementations could run faster and support sequence
packing. We spent time optimizing around constraints of the existing backend
that a different backend could remove.

B3 moved **both NVARC and FLUX to FlashAttention-3 (FA3) with sequence packing**.
Sequences of different lengths share one call without padding, while their
attention stays separate. This replaces B2's padding catalogs and shape-based
batch selection in both models.

FLUX packs each target's text prefix and image tokens into a separate sequence
and groups these sequences under a 12,288-token budget. Both its double-stream
and single-stream blocks use FA3 for forward and backward.

NVARC packs all 16 sources into one call. We also stop its forward pass after
block 27, where the last required hidden states are available. This skips nine
of its 36 transformer blocks: **25% of the blocks no longer run**.

Across all measured steps, B3 reached **5.250 targets/s**, with a median
optimizer step of **9.06 s**: **25.0% more throughput than B2**. Each update
still used the same 48 targets in the same logical order.

The [benchmark overview](README.md) explains the shared dataset, hardware,
measurement protocol, and comparison across variants.

## From alignment to packing

The starting question was whether better-aligned padding lengths could make
the B2 batches faster. NVARC alignment tests improved some shapes but gave
no generally better rounding rule.

We then investigated other attention backends: first FA2 with the existing
NVARC groups, then with unpadded packing. Variable-length attention made it
possible to remove the shared padding lengths altogether. Further backend
comparisons led to FA3. For FLUX, the investigation also covered forward and
backward agreement, modulation gradients, and how many tokens fit in memory.

The component reports cover these experiments:

- [B3 NVARC analysis](b3-nvarc.md)

## How B3 ran

B3 used the same 960 augmented sources and three eligible targets per source
as the earlier variants. NVARC and the VAE stayed frozen; the complete FLUX
transformer was trainable.

1. Read the next 16 sources in their recorded order. Two CPU workers loaded,
   augmented, formatted, and tokenized upcoming sources in the background.
2. Concatenate the source sequences without padding and run NVARC once.
   Each source has its own causal attention boundary and starts its position
   IDs at zero. Keep the raw hidden states after blocks 9, 18, and 27, then
   stop; the remaining blocks and language-model head are not needed.
3. Create the individual target examples from their hidden-state prefixes.
   Encode all 48 target images in one VAE call.
4. Append the examples to the FIFO queue and select its next 48 targets for
   one optimizer update. Assign noise and timesteps in that logical order.
5. Pack those targets into FLUX calls with at most 12,288 joint tokens each.
   A target costs its exact text-prefix length plus 900 image tokens. Place
   larger targets first, choosing the tightest remaining space. Keep each
   target whole and inside its selected optimizer batch.
6. Run FLUX forward and backward for each pack. Each target has a separate
   noncausal FA3 attention segment and its own timestep modulation. Backward
   sums the modulation contributions in FP32. A pack of `m` targets contributes
   `mean_loss * m / 48`; a smaller final optimizer batch uses its actual
   target count as the denominator.
7. Apply one optimizer update and release gradients before the next frozen
   NVARC/VAE preparation phase.

Neither model uses a padding catalog. NVARC no longer needs length-based
batch selection. FLUX still groups targets to stay within its token budget,
but no longer selects batches from measured padded shapes.

### Run parameters

| Parameter | B3 value |
| --- | --- |
| NVARC preparation window | 16 consecutive sources |
| NVARC physical batch | One packed call for the complete window |
| NVARC hidden states | Raw outputs after blocks 9, 18, and 27; execution stops after block 27 |
| VAE microbatch size | 48 target images per call |
| FLUX microbatch size | Variable target count under 12,288 joint tokens per call |
| Optimizer batch size | 48 targets, accumulated across the selected FLUX packs |
| Length policy | Exact sequence lengths; no padding or alignment |
| Attention | FA3 variable-length attention: causal in NVARC, noncausal in FLUX |
| Input order | FIFO optimizer membership; FLUX packs may reorder targets within each step |
| DataLoader workers | 2, with ordered delivery and `prefetch_factor=8` |
| Precision | Frozen NVARC in BF16; frozen VAE in FP32; FLUX parameters in FP32 with BF16 compute and FP32 modulation sums in backward |
| Activation checkpointing | Disabled |

## Benchmark result

Each run started with ten warm-up steps before timing the next 50 steps.
The warm-up steps are excluded from the timing results. All three runs used
the same inputs on one H200.

| Run | Median step | p95 step | Targets/s | Peak allocated | Peak reserved |
| --- | ---: | ---: | ---: | ---: | ---: |
| Run 1 | 9.10 s | 10.60 s | 5.241 | 131.59 GiB | 137.44 GiB |
| Run 2 | 9.06 s | 10.60 s | 5.256 | 131.59 GiB | 137.44 GiB |
| Run 3 | 9.05 s | 10.59 s | 5.254 | 131.59 GiB | 137.44 GiB |
| **Median of the three runs** | **9.06 s** | **10.60 s** | **5.254** | **131.59 GiB** | **137.44 GiB** |
| B3: all 150 measured steps combined | 9.06 s | 10.63 s | 5.250 | 131.59 GiB | 137.44 GiB |
| [B2](b2.md): all 150 measured steps combined | 11.32 s | 13.47 s | 4.201 | 126.48 GiB | 133.06 GiB |
| [B1](b1.md): all 150 measured steps combined | 13.91 s | 15.77 s | 3.461 | 113.90 GiB | 118.84 GiB |
| [B0](b0.md): all 150 measured steps combined | 15.45 s | 17.59 s | 3.094 | 113.91 GiB | 138.12 GiB |

B3 delivered **25.0% more targets/s than B2**, **51.7% more than B1**, and
**69.7% more than B0**. Peak allocated memory increased by **5.11 GiB** from B2.
This measures the combined changes; it does not separate the gains from FA3,
packing, and NVARC's earlier exit.

| Work per optimizer step | B2 | B3 |
| --- | ---: | ---: |
| Mean NVARC calls | 4.14 | 1.00 |
| NVARC processed / real token positions | 1.22x | 1.00x |
| Mean FLUX microbatches | 18.68 | 12.02 |
| FLUX text padding above real positions | 10.14% | 0.00% |

These counts cover the 50 measured steps per run. B3's FLUX packs contained
between one and eight targets; every pack stayed within the 12,288-token budget.
